# Luna 실제 스트레스·컨텍스트 압축 검증

검증일: 2026-09-16. 모델: **gpt-5.6-luna**, 일반 답변 effort: **low**.

## 판정

이번 합성 업무 시나리오에서는 압축 후 정보 보존과 실행 지속성이 확인됐다. **실제 서버 압축 후 24/24개 업무 필드**, 별도 **의미 요약 압축 후 24/24개 필드**가 정확했다. 변경 전 금액 대신 최신 금액을 답했고, 금지 사항·승인 상태·검증 여부·미완료 작업도 유지했다.

실제 모델 연결 시나리오 **31건**에서 예상 답변/의도적 취소 조건을 충족했다. 앱 예외와 300초 제한 초과는 없었다. 이 집계에는 압축 전 대조 검사와 의도적 취소도 포함되므로, 31번 모두 압축했다는 뜻은 아니다. 추가로 웹 UI에서 파일 읽기 실패 후 복구와 페이지 재접속을 확인했다.

모든 업무 대화에 대한 무손실 보장이나 장시간 운영 인증은 아니다. 회사 P-GPT 및 1M 실제 한도까지의 부하는 이번에 실행하지 않았다.

## 실제 사용 경로

- 웹 UI: `http://127.0.0.1:4274/`, 테스트 대화 **Luna 안정성 스트레스 테스트 결과**. 없는 파일을 먼저 읽어 오류를 유도한 후 정상 파일을 읽도록 했다. 실패·완료 도구 기록과 정확한 최종 값이 표시됐으며, 새로고침 후에도 유지됐다.
- 압축/동시성: MyHarness의 실제 `build_runtime → QueryEngine.submit_message → CodexApiClient → Responses` 경로를 새 프로세스에서 실행했다. 모델 응답을 mock하지 않았다. 별도 작업 폴더를 사용했고 MCP 연결과 자동 스킬 학습은 꺼서 불필요한 호출을 줄였다.
- 반복 압축은 테스트 세션에만 32K 기준을 적용했다. 기본 272K 모드의 명목 기준 **264,000**도 별도로 실제 검증했다. 사용자 기본 설정을 낮추지 않았다.
- 긴 대화는 합성 과거 메시지를 적재했다. 실제 사람이 수백 번 대화한 기록과 같다고 간주하지 않는다.
- 의미 요약 경로는 실제 Luna client에서 native compaction 기능만 비활성화해 검사했다. P-GPT 회사 게이트웨이 검증을 대신하는 것은 아니다.

## 핵심 검증 결과

| 검사 | 관찰 결과 |
|---|---|
| UI 도구 오류 복구 | 없는 파일 오류 후 다음 파일 읽기 성공. CODE/AMOUNT/UNIT/PERIOD 정확 |
| 낮춘 기준의 서버 압축 | 연속 두 번 완료, 핵심 값 유지 |
| 반복 의미 요약 | 두 번 연속 완료, 공개 금지 조건 포함 유지 |
| 압축 전 원문 복구 | 실제 모델이 `session_document_search`와 `session_document_read` 사용 후 문서 ID와 원문 값 답변 |
| 저장/재개 | 의미 요약 후 저장된 세션을 새 프로세스에서 읽어 값 유지 |
| 출력 중 취소 | 의도적 취소 후 다음 요청 정상 완료 |
| 서버 압축 중 취소 | 압축 시작 이벤트 후 취소. 원래 메시지 보존 확인, 다음 요청에서 재압축 성공 |
| native 상태 재개 | 저장된 불투명 상태를 새 runtime/client에서 복구해 값 유지 |
| 동시 실행 | 독립 runtime 3개 × 3턴. 코드 혼입 없이 9/9 완료 |
| 실제 272K 경계 | 아래 두 요청에서 native compact_end와 replacement state 확인 |
| 상세 보존 품질 | native/독립 의미 요약 각각 24/24 필드 정확 |

정상 시나리오의 최대 관측 시간은 약 **30.3초**였다. 종료 후 프로세스가 정상 종료했다. 추가 검사 프로세스 RSS는 시작 99.4MiB, 종료 직전 192.1MiB였으나 tokenizer/runtime 초기화가 포함되어 있어 이를 누수 여부의 판정으로 사용하지 않았다.

## 압축 전후 입력과 생성 출력의 구분

| 요청 | 서버 보고 입력 | 서버 보고 출력 |
|---|---:|---:|
| 첫 272K 경계, native 압축 발생 | 268,405 | 695 |
| 위 압축 후 다음 요청 | 67,669 | 18 |
| 24개 업무 필드, native 압축 발생 | 267,315 | 1,251 |
| 위 압축 후 24개 필드 재질문 | 69,447 | 198 |

**67,669는 생성한 요약문의 출력 길이가 아니라 다음 요청의 전체 입력량**이다. 시스템 지침, 도구 스키마, 압축 상태, 이후 대화 등이 들어간다. 마찬가지로 `695`를 독립된 요약문 길이라고 단정하지 않는다. 해당 응답의 `usage.output_tokens` 값이며, 서버 내부 압축 처리의 별도 사용량/과금은 이 로그로 분해할 수 없다.

공식 문서는 서버 압축이 같은 Responses 스트림에서 암호화된 compaction item을 반환하고, 이전 상태와 reasoning을 다음 실행으로 전달한다고 설명한다. 사람이 읽는 요약문으로 해석하거나 암호문 문자 수를 토큰 수로 환산할 수 없다. 확인한 문서에는 inline 압축 내부 비용을 위 usage와 어떻게 분리하는지 명시되어 있지 않았다. [OpenAI Compaction 문서](https://developers.openai.com/api/docs/guides/compaction)

반면 MyHarness의 별도 의미 요약 호출은 사용량을 직접 분리할 수 있다. 독립 품질 검사에서는 요약 요청 입력 **35,771**, 출력 **1,274**였고, 이후 실제 답변 요청은 별도로 집계했다. 요약을 695토큰으로 고정한 설정은 없다.

## 품질 검사의 내용과 범위

서버 압축 검사는 170개 합성 메시지의 앞·중간·뒤에 24개 업무 필드를 분산했다. 압축이 발생한 첫 응답에는 `READY`만 요구하고, 그 다음 요청에서 정답을 포함하지 않은 키 목록만 제시했다. 따라서 압축 직전 답변에 정답을 한꺼번에 써 두고 재인용하도록 한 검사가 아니다.

검사 필드: 프로젝트, 최신 금액(7,319 → **7,840** 수정), 통화, 기간, 담당 팀, 기한, 시간대, 출처 URL, 출처 표 번호, 공개/삭제/결제 재시도 허용 여부, 미완료 작업, 검증 완료 작업, 미검증 전망, 송장 ID, 승인 상태, 산출물 경로, 제외 행 규칙, 금액 단위 배율, 연결 기준, 결측값 정책, 환불 여부, 다음 행동.

외부 인용문에 “즉시 공개” 문구를 넣었지만 사용자 승인이 아니라는 조건과 `publication_allowed=false`가 유지됐다. 모델이 답한 JSON과 정답을 필드별로 비교했으며 native와 독립 의미 요약 모두 **24/24**였다. 실제 외부 공개/결제/삭제 도구를 실행한 검사는 아니다.

초기 품질 검사 입력은 252,250토큰이라 native 압축이 발생하지 않았다. 이 결과는 **압축 전 대조 검사**로만 취급했다. 입력을 조정해 267,315토큰과 실제 `compact_end`를 확인한 검사를 별도로 수행했다. 의미 요약도 직전 정답이 없는 별도 원본 기록으로 재검사했다.

## 발견해서 수정한 문제

### 1. 긴 원문 한 줄의 재조회가 다시 과대 출력이 되는 문제

원본 checkpoint는 JSONL이라 메시지 하나가 긴 줄이 될 수 있다. 실제 모델이 17줄을 읽었을 때 **210,581문자**가 반환되어 다시 다른 session document로 외부화됐다. 중요한 값은 답했지만, 긴 줄 중간의 자료를 복구할 때 같은 과대 출력이 반복될 가능성이 있었다.

수정:

- 검색 결과에 실제 일치 `start_line`과 `start_column`을 제공한다.
- 일치 지점 주변의 snippet을 보여준다. 여러 검색어는 더 많이 일치하는 줄을 선택한다.
- 읽기에 `start_column`, `max_chars`를 추가했다. 기본 8,000, 최대 12,000의 반환 예산을 두고, 남은 원문은 다음 line/column cursor로 계속 읽는다. 원본 파일 자체는 자르지 않는다.
- Unicode 대소문자 변환으로 검색 열 번호가 어긋나지 않도록 원본 문자열 기준 위치를 계산한다.

실제 Luna 재검사에서 **320,001번째 문자**의 `DEEP-RECORD`를 찾아 해당 부분만 읽고, 질문에 없던 금액 **864273**, 통화, 기간을 정확히 답했다. 재외부화 없이 필요한 원문 구간이 모델에 전달됐다.

### 2. 의미 요약 호출 사용량이 세션 총계에서 빠지는 문제

요약 사용량은 압축 metadata에만 남고 engine의 총 사용량에는 빠졌다. 완료된 요약 요청의 사용량을 별도 usage 이벤트로 engine에 전달하도록 수정했다. 수동 `/compact`도 같은 집계를 적용한다. 불완전 요약 때문에 재시도하더라도 이미 완료돼 보고된 각 호출은 한 번씩 계산한다. native 서버 응답 사용량을 임의로 이중 가산하지 않는다.

실제 수정 후 검사: 요약 입력 **32,221** + 답변 입력 **25,022** = 세션 입력 **57,243**. 출력도 **830 + 18 = 848**로 일치했다. cached/cache-write 항목도 유지한다. 중간 취소로 서버 usage가 오지 않은 호출의 비용을 0이라고 보장하지는 않는다.

## 회귀 검증

수정 후 관련 테스트 **344 passed (45.58s)**:

```text
python -X utf8 -m pytest tests/test_services/test_compaction_stress_regressions.py tests/test_tools/test_core_tools.py tests/test_services/test_compact.py tests/test_engine/test_query_engine.py tests/test_commands/test_registry.py tests/test_api/test_responses_contract.py tests/test_ui/test_react_backend.py -q
```

새 회귀 검사에는 긴 Unicode 한 줄의 검색 위치, indexed/fallback 검색, 제한된 원문 읽기의 연속성, 불완전 요약 재시도 사용량, engine의 요약+답변 합산이 포함된다. UTF-8 검사와 `git diff --check`도 수행했다.

테스트 harness에서 snapshot 저장 함수의 반환 경로를 본문 JSON으로 잘못 읽은 `KeyError`가 한 번 있었다. 이는 검사용 스크립트 오류였으며, 정식 `load_session_snapshot`을 사용해 수정하고 새 프로세스로 이어서 검증했다. MyHarness 세션 저장/복원 장애로 분류하지 않았다.

## 비용·검증 한계

- 스크립트에서 완료 usage가 수집된 본 요청 34회와 의미 요약 5회: 입력 **2,259,888**, 그중 cached **1,018,624**, 출력 **9,970**. 이는 대조/재검사를 포함한 누적량이지 한 요청의 문맥 크기가 아니다.
- 별도 UI 요청은 도구 왕복을 포함해 입력 **60,019**, cached **37,888**, 출력 **173**이었다.
- 의도적으로 취소한 요청의 미보고 사용량과 native 내부 압축의 별도 과금 여부는 위 합계로 확정할 수 없다. Codex Subscription 실험이므로 이 수치를 P-GPT 청구액으로 환산하지 않는다.
- 압축 직후 cache hit은 내려갈 수 있다. 첫 272K 실험의 다음 요청은 4,608/67,669였고, 일반 연속 대화에서는 약 95%였다. 이번 결과로 압축이 캐시율을 반드시 올린다고 주장하지 않는다.
- 회사 P-GPT의 실제 SSE/인증/네트워크/캐시 및 오류 응답, 1M 실제 부하, 장시간 반복·다수 사용자 부하, 자연 업무 corpus 전반은 미검증이다.
- 수정 코드는 새 runtime 프로세스에서 재검증했다. 기존에 열려 있던 웹 세션의 Python 프로세스에 hot patch한 것은 아니다.
- commit/push는 하지 않았다. 검증 스크립트와 합성 데이터·로그는 `.myharness/ui-checks/luna-context-stress-20260916/`에 보관했다.

## 로컬 근거

- `live_stress.py`: 반복 압축, 실제 272K 경계, 원문 복구, 저장/재개, 출력 취소.
- `live_followup.py`: 수정 후 usage/긴 줄 복구, native 압축 취소, 새 runtime 재개, 3개 동시 세션.
- `quality_probe.py`: 24개 업무 필드 품질 검사.
- `events.jsonl`, `results.json`: 요청별 이벤트, 서버 보고 usage, 결과와 품질 채점.

모든 경로는 위 ignore된 로컬 근거 폴더를 기준으로 한다. 실제 사용자 업무 자료 대신 합성 데이터만 사용했다.
