# 한글 조판

라틴 기준으로 짠 타이포 설정을 한글에 그대로 쓰면 티가 난다. 이 문서는 발표 크기(60~130px)에서 특히 드러나는 것들을 다룬다.

## 서체

발표 덱은 큰 글씨가 화면을 지배하므로, 큰 글씨에서 획과 자간이 버티는 서체를 골라야 한다.

| 서체 | 성격 | 조달 |
|---|---|---|
| **Paperlogy** | 발표 슬라이드용으로 설계된 한글 고딕. 9굵기. 큰 글씨에서 획이 무너지지 않는다 | `cdn.jsdelivr.net/gh/fonts-archive/Paperlogy/Paperlogy-{4Regular,6SemiBold,8ExtraBold,9Black}.woff2` |
| **Pretendard** | 현대적 지오메트릭. UI·본문에 강함 | `cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css` |
| Noto Sans KR | 안전하지만 어디서나 보이는 기본값 | Google Fonts |
| Gothic A1 | 자폭이 고르고 표에서 덜 흐트러짐 | Google Fonts |

**기본값은 Paperlogy다.** 굵기는 실제로 쓰는 넷만 받는다(400/600/800/900) — 아홉 개를 다 받으면 첫 화면이 늦어진다.

피할 것:

- **명조(Noto Serif KR, Batang 등)를 제목에 쓰지 않는다.** 발표 화면에서 궁서체로 읽히고, 한국어 사용자에게 낡은 인상을 준다. 편집물 느낌이 필요하면 다른 방법을 찾는다.
- **IBM Plex Sans KR** — 한글 큰 글씨에서 자간이 헐렁하고 획이 기계적이다. 라틴은 좋지만 한글 제목에는 약하다.

폴백은 반드시 시스템 서체까지 잇는다. 행사장 네트워크를 못 믿는 경우 CDN이 늦거나 실패한다.

```css
--font-display:'Paperlogy','Malgun Gothic','Apple SD Gothic Neo',sans-serif;
```

## 모노 서체는 라틴·숫자 전용이다

이게 가장 자주 밟는 함정이다.

**IBM Plex Mono, JetBrains Mono 같은 코딩용 모노 서체에는 한글 글리프가 없다.** 한글이 섞인 요소에 모노를 걸면 그 글자만 대체 서체로 떨어지고, 거기에 넓은 `letter-spacing`까지 겹치면 이렇게 된다.

```
잘못:  마 스 터   트 랙        (모노 + letter-spacing:.10em)
정상:  마스터 트랙            (본문 서체 + letter-spacing:.02em)
```

모노는 ID·해시·URL·순수 숫자에만 쓴다. 한글이 하나라도 섞이면 본문 서체로 돌린다.

혼용된 문구는 **쪼갠다.**

```html
<!-- 잘못 -->
<span class="mono">SIG-616AB52ADDF4 · Claim 19건 · 공개 원문 3건</span>

<!-- 정상 -->
<span>
  <b class="mono">SIG-616AB52ADDF4</b> · Claim <b class="mono">19</b>건
  · 공개 원문 <b class="mono">3</b>건
</span>
```

검증은 `scripts/audit.js`가 자동으로 한다(모노가 걸린 요소에 한글 정규식 스캔).

`text-transform:uppercase`도 같은 계열의 실수다. 한글에는 아무 효과가 없고, 영문 라벨에만 의미가 있다. 한글이 섞인 라벨에 걸어두면 영문 부분만 대문자가 되어 들쭉날쭉해진다.

## 자간

라틴 디스플레이 타입은 `-0.02em` ~ `-0.04em`까지 조여야 좋아 보이지만, **한글은 그렇지 않다.** 한글 음절은 이미 정사각형에 꽉 차 있어서 음수 자간을 크게 주면 글자가 서로 붙는다.

| 용도 | 값 |
|---|---|
| 한글 제목 | `-0.012em` ~ `-0.018em`까지. 그 이상 조이지 않는다 |
| 한글 본문 | `0` |
| 라벨·kicker | `0.01em` ~ `0.02em`. 넓히려면 이 정도까지만 |
| 라틴 전용 제목 | `-0.02em`까지 가능 |

## 줄바꿈

```css
body{ word-break:keep-all; }
```

이게 없으면 한글이 낱자에서 갈라진다 — "선행조건"이 "선행조 / 건"이 된다. 한국어는 어절 단위로 끊어야 읽힌다.

부작용으로 긴 URL이나 해시가 컨테이너를 넘칠 수 있다. 그런 요소에만 따로 예외를 준다.

```css
.url, .hash { word-break:break-all; }
```

## 행간

한글은 라틴보다 행간이 더 필요하다. 받침이 있어 글자 높이가 실제로 크기 때문이다.

| 용도 | line-height |
|---|---|
| 큰 제목 (90px+) | `1.1` ~ `1.14` |
| 중간 제목 (50~70px) | `1.22` ~ `1.3` |
| 본문 | `1.55` ~ `1.6` |
| 표 셀 | `1.45` |

## 크기 (1920×1080 무대 기준)

프로젝터 뒷줄에서 읽히는 것이 기준이다. 화면으로 볼 때 "좀 큰가?" 싶은 정도가 대개 맞다.

| 요소 | 크기 |
|---|---|
| 표지 제목 | 110 ~ 130px |
| 장 제목 (h2) | 60 ~ 70px |
| 리드 문장 | 34 ~ 38px |
| 본문 | 27 ~ 31px |
| 표 | 26 ~ 29px |
| 라벨·메타 | 19 ~ 23px |
| 결론 바 | 30 ~ 34px |

19px 아래로 내려가는 텍스트가 있으면 그 정보가 정말 필요한지 다시 본다. 안 읽히는 정보는 없는 정보다.
