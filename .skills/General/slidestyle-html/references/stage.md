# 무대와 스케일링

발표 덱의 레이아웃 사고는 대부분 **크기가 바뀌는 순간**에 일어난다. 전체화면 진입, 외부 모니터 연결, 프로젝터 해상도 협상, 숨은 탭에서 미리 열어두기. 이 문서는 그 순간들을 견디는 구조를 다룬다.

## 왜 고정 무대인가

반응형으로 짜면 창 크기마다 줄바꿈이 달라지고, 그러면 **넘침을 미리 검증할 수 없다.** 1024px에서 맞춘 장이 1440px에서 세 줄이 되고, 프로젝터의 1280×800에서 또 달라진다. 발표 자료는 되돌릴 기회가 없으므로 이 불확실성을 없애는 편이 낫다.

그래서 논리 좌표를 1920×1080으로 고정하고 전체를 `transform: scale()` 한 장으로 축소한다. 창이 어떻게 바뀌어도 **내부 레이아웃은 재계산되지 않는다.** 검증한 화면이 그대로 발표에 나온다.

16:9가 아닌 화면에서는 위아래 또는 좌우에 여백이 생긴다. 그 여백은 `--void` 색으로 두면 자연스럽다.

## 세 가지 함정

### 1. `flex-shrink`가 무대를 눌러버린다

`#viewport`를 flex 컨테이너로 두고 그 안에 1920px 무대를 넣으면, flex 항목의 기본 `flex-shrink:1` 때문에 무대 폭이 **창 폭까지 압축된다.** 높이는 주축이 아니라 그대로 남으므로 결과는 가로만 찌그러진 화면이다.

눈으로는 "글자가 좀 좁네" 정도로 보여서 놓치기 쉽다. 반드시 `flex:none`을 준다.

```css
#stage{ flex:none; width:var(--stage-w); height:var(--stage-h); }
```

검증: 무대의 `getBoundingClientRect()` 비율이 `1.778`인지 본다. `1.185` 같은 값이 나오면 눌린 것이다.

### 2. `scale(0)`으로 화면이 사라진다

숨은 탭에서 로드되거나 레이아웃 전에 스크립트가 돌면 `innerWidth`가 `0`이다. 그대로 계산하면 `scale(0)`이 박히고, 화면이 통째로 사라진 뒤 `resize` 이벤트가 올 때까지 복구되지 않는다.

발표 직전에 탭을 미리 열어두는 것은 아주 흔한 행동이라, 이 버그는 실제로 발표장에서 터진다.

```js
function fitStage(){
  const w = innerWidth  || document.documentElement.clientWidth;
  const h = innerHeight || document.documentElement.clientHeight;
  if (!w || !h) { requestAnimationFrame(fitStage); return; }   // 0이면 다음 프레임에 다시
  stage.style.transform = `scale(${Math.min(w/1920, h/1080)})`;
}
```

`resize` 하나만 듣지 말고 `load`, `visibilitychange`, `fullscreenchange`, `orientationchange`, `ResizeObserver`까지 붙인다. 전체화면 진입은 `resize`를 놓치는 브라우저가 있다.

### 3. 두 곳에서 무대 크기를 계산하기

CSS 토큰과 JS가 각각 무대 크기를 계산하면 언젠가 어긋나고, 그러면 장이 반쯤 걸쳐 선다. 크기의 원본은 한 곳(`--stage-w` / `--stage-h`)이고 JS는 그 값을 읽거나 같은 상수를 공유한다. 불가피하게 중복되면 **주석으로 서로를 가리켜** 함께 고치게 만든다.

## 여백과 안전 영역

```
padding: 72px 96px 84px;
```

아래를 더 두는 이유는 진행 표시(장 번호·챕터 태그·진행 바)가 거기 있기 때문이다. 이 요소들은 `.slide` 밖에 두고 `z-index`를 올린다 — 슬라이드가 전환될 때 같이 사라지면 안 된다.

프로젝터는 화면 가장자리를 잘라먹는 경우가 있다. 중요한 정보를 가장자리 40px 안쪽에 두지 않는다.

## 모바일

QR로 청중이 자기 폰에서 여는 경우를 생각하면, 무대는 그대로 축소되어 들어가므로 글자가 작아진다. 그래도 읽히는 이유는 애초에 프로젝터 뒷줄 기준으로 크게 잡았기 때문이다. 별도 모바일 레이아웃을 만들 필요는 없다 — 만들면 두 벌을 검증해야 한다.

스와이프는 붙인다. 폰에서 키보드가 없다.

## 인쇄·PDF

백업 PDF는 `scripts/export_pdf.py`가 헤드리스 브라우저로 장당 1페이지를 뽑는다. 단계 노출은 PDF에서 의미가 없으므로 **모든 단계를 노출한 상태로** 인쇄한다(스크립트가 처리한다).
