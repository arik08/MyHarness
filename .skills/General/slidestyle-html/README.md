# slidestyle-html

발표용 슬라이드 덱을 **단일 HTML 파일**로 만드는 Claude Code 스킬.

의존성 없음. 파일 하나를 브라우저에서 열면 끝이다. 16:9 고정 무대, 키보드·스와이프 내비게이션, 클릭마다 한 줄씩 나오는 단계 노출, 해시 딥링크, 그리고 **발표 당일에 터질 결함을 미리 잡는 검증 하네스**까지 들어 있다.

## 설치

```bash
git clone https://github.com/arik08/slidestyle-html.git ~/.claude/skills/slidestyle-html
```

Claude Code가 다음 세션부터 자동으로 인식한다. 확인은 `/help` 또는 스킬 목록에서.

## 무엇이 들어 있나

```
SKILL.md              작업 순서와 판단 기준

references/

  reveal.md           단계 노출·SVG 순차 드로잉·라이브 위젯
  korean-type.md      한글 조판 (모노 함정, 자간, 줄바꿈, 크기표)
  palette.md          브랜드색 하나에서 팔레트 파생, 다크/밝은 경로
  charts.md           막대·타임라인 차트, 차트를 쓸지 판단

```

## 왜 검증이 핵심인가

덱의 결함은 대부분 발표 당일에 드러난다. 눈으로는 안 잡히는 것들이 있다.

이 스킬을 만들며 실제로 잡은 것들:

| 결함 | 증상 |
|---|---|
| `flex-shrink`가 무대를 눌렀다 | 1920px 무대가 창 폭까지 압축돼 **가로만 찌그러진 화면**. 눈으로는 "글자가 좀 좁네" 정도로 보인다 |
| 숨은 탭 로드 시 `scale(0)` | `innerWidth`가 0인 시점에 계산돼 화면이 통째로 사라진다. 발표 직전 탭을 미리 열어두면 재현된다 |
| SVG `marker-end`가 선보다 먼저 렌더 | 화살촉만 공중에 떠 있는 상태로 애니메이션이 시작된다 |
| 모노 서체에 갇힌 한글 | 코딩용 모노에는 한글 글리프가 없어 대체 서체로 떨어지고, 넓은 자간까지 겹쳐 `마 스 터  트 랙`이 된다 |
| 그라데이션 위 대비 미달 | 계산된 `background-color`로는 **절대** 검사되지 않는다. 발광 레이어가 지나가는 자리에서 보조 텍스트가 3:1 아래로 떨어진다 |
| 카운트업이 하드코딩 장 번호에 묶임 | 장을 하나 끼워 넣으면 조용히 죽는다 |
| 윈도우 cp949 콘솔 크래시 | 파이썬 스크립트가 한글을 출력하다 `UnicodeEncodeError`로 죽는다 |

`scripts/audit.js`가 16종을 자동으로 잡는다. 대비는 픽셀에서 재야 하므로 `contrast.py`가 따로 있다 — 배경만 렌더한 스크린샷에서 **블록 평균**을 낸 뒤 최명부를 찾는다(1~2px 입자를 배경으로 오독하지 않기 위해서다).

## 한글 조판

라틴 기준 설정을 한글에 그대로 쓰면 티가 난다. `references/korean-type.md`가 다루는 것:

- **모노는 라틴·숫자 전용.** 한글이 하나라도 섞이면 본문 서체로 돌린다
- **명조를 제목에 쓰지 않는다.** 발표 화면에서 궁서체로 읽힌다
- **음수 자간은 `-0.018em`까지.** 한글 음절은 이미 정사각형에 꽉 차 있다
- **`word-break: keep-all`.** 없으면 "선행조건"이 "선행조 / 건"으로 갈라진다
- 크기표 (1920×1080 무대 기준, 프로젝터 뒷줄 기준)

기본 서체는 [Paperlogy](https://github.com/fonts-archive/Paperlogy) — 발표 슬라이드용으로 설계된 한글 고딕이라 큰 글씨에서 획이 무너지지 않는다.

## 분량은 클릭 수로 센다

장 수만 세면 크게 빗나간다. 단계 노출이 붙으면 한 장이 다섯 박자가 되기 때문이다.

| 시간 | 총 박자 | 예 |
|---|---|---|
| 5분 | 25~35 | 7장 × 평균 4단계 |
| 10분 | 50~70 | 14장 × 평균 4단계 |
| 15분 + 라이브 데모 | 데모 제외 40~55 | 덱이 데모의 앞뒤를 감싼다 |

`audit.js`가 장별 단계 수를 세어주므로 만든 뒤 총 박자를 확인한다.

## 미감은 위임한다

팔레트·타이포·서명 요소를 브리프에 맞게 정하는 판단은 `frontend-design` 스킬이 다룬다. 이 스킬은 그 위에 얹는 **덱 역학**과 **검증**만 담당한다. 둘을 같이 쓰는 것을 전제로 만들었다.

## 의존성

| 스크립트 | 필요한 것 |
|---|---|
| `audit.js` | 없음 (브라우저 페이지 컨텍스트에서 실행) |
| `contrast.py` | `pip install pillow` |
| `qr_svg.py` | `pip install qrcode` |
| `export_pdf.py` | Chrome 또는 Edge (윈도우는 Edge가 항상 있다) |

덱 자체는 Paperlogy와 IBM Plex Mono를 CDN에서 받는다. 오프라인이면 시스템 고딕으로 폴백되며 레이아웃은 깨지지 않는다.
